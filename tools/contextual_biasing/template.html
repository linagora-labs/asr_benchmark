Contextual Biasing ASR Benchmark

How well speech recognition models write the terms of a list (drug names, rare words, company names) without the list, and when the list is given to the model (prompt, hotwords or boosting). Each run with a list is compared with the run of the same model without it, on the same terms.

Metrics

  • WER: word error rate of the whole transcription (normalized text).
  • B-WER: word error rate on the words of the list terms of the reference; U-WER: on the other words.
  • F1, R, P: F1, recall and precision of the list terms (each occurrence of a term of the targets, in the reference and in the transcription).
  • FA/h: false alarms per hour, list terms written although not spoken.
  • Runaway: percentage of the utterances whose transcription runs away (more than twice as many words as the reference, plus 10): loops, invented sentences, prompt recited. A few of them weigh a lot on B-WER, WER and FA/h.
  • RTFx: seconds of audio transcribed per second (higher is faster), on one NVIDIA DGX Spark (GB10), as the benchmark runs each model: vLLM servers with 32 to 128 concurrent requests, NeMo and VibeVoice-ASR in batches (64; 4 to 16 with the long lists), faster-whisper one file at a time. It compares the cost of the lists for a model more than the models with each other. "~": approximate, taken from the logs (time of the whole run, model loading and scoring included, hence underestimated for short runs). A list given in the prompt is processed with every request: the longer the list, the slower.
  • Case sensitive: a term is correct only if written as in the list given to the model (as in the targets for runs without list); the case of the other words is not checked.
  • Lists: local lists only hold terms of the utterance; the others are global lists (one list for the whole test set). _upper: the same list in capitals, given to check that the model writes the terms as given (to read with "Case sensitive").
